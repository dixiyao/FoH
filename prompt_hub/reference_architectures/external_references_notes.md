# External references -- what each system actually is, and how much to trust it

Read this if you want to know how much weight a claim elsewhere in this directory deserves. None of the four systems below were reproduced verbatim anywhere in this reference material -- everything attributed to them elsewhere is an adapted idea, not copied code, and license status for several of them is closed or unclear, which is a second, independent reason nothing here is a code dump.

## omp.sh / "Oh My Pi" (oh-my-pi)

**What it is:** A real, actively developed terminal coding-agent CLI/TUI (in the same category as Claude Code or Aider), a heavily extended fork of Mario Zechner's minimal "Pi" agent, maintained by Can Bölük under the `oh-my-pi` name. Not a general agent-orchestration platform, not a self-rewriting system.

**License / open-source status:** Yes, genuinely open. MIT License, confirmed directly against the GitHub API (`license.key == "mit"`) on `github.com/can1357/oh-my-pi`. Vendored third-party code keeps its own original licenses.

**Verdict:** The strongest of the four as an architectural reference, and the only one independently verified by reading actual source files (not just a rendered marketing page) -- a real 80k-LOC-plus TypeScript+Rust monorepo with a plan-mode subsystem, a capability/tool/skill/MCP composition system, git-worktree-isolated subagents with schema-validated outputs, multiple memory backends, a live "advisor" second-model critique mechanism, a content-hash-anchored ("hashline") edit format, and an internal benchmark harness used to justify prompt/format changes with real numbers. Its one genuine self-modifying behavior (the `autolearn`/`managed-skills` feature) is explicitly labeled experimental in its own source and is scoped to writing bounded, sanitized skill markdown files -- not code, weights, or the base prompt. Treat the specific benchmark percentages in its marketing (e.g. claimed token-reduction or pass-rate numbers) as the maintainers' own self-reported figures, not independently reproduced here.

## zcode (Z.ai / Zhipu AI)

**What it is:** A commercial "Agentic Development Environment" -- an Electron desktop app plus a companion CLI -- wrapping Z.ai's GLM model family with an agent loop, bundled dev tools, hooks, and a Skills/Plugins extension system. A real, currently-shipping coding-agent product, not a research artifact.

**License / open-source status:** Closed. The harness/application itself is proprietary and free-to-download, not open-source; only the underlying GLM model weights are open (GLM-5.2 under MIT on Hugging Face; GLM-5.3, the model the live product targets as of this research, had not had its weights published yet). No official source repository for zcode itself was found -- only unofficial third-party binary-repackaging shims.

**Verdict:** Genuinely thin as an architectural reference, because there is no source to inspect -- every claim about it traces back to Z.ai's own docs/changelog/marketing copy, not independent code reading. Its documented feature vocabulary (hooks with near-identical lifecycle names to Claude Code's, a subagent/"Agent tool" pattern, Skills, Plugins, AGENTS.md, Plan mode) closely parallels Claude Code's own publicly documented architecture in naming and shape, which reads as deliberate design-parallelism/interop positioning rather than evidence of a shared or novel architecture. One specific claim -- that it is "built on Anthropic's Claude Agent SDK" -- appeared in exactly one auto-summarized page fetch and nowhere else (the official docs explicitly say no SDK is disclosed); treat that specific claim as a likely artifact of that one summarization, not a documented fact. The one part of zcode worth taking seriously as a design idea regardless of the vendor-only sourcing is its documented Goal-Mode act/verify split (see `planning_and_verification.md`) -- concrete and sensible as a pattern, even though it cannot be verified against real code.

## NousResearch/hermes-agent (+ hermes-agent-self-evolution)

**What it is:** A general-purpose personal/ops AI agent framework -- a CLI plus a gateway for chat platforms (Discord, Telegram, etc.) -- with broad terminal/sandbox tool access (Docker, SSH, Modal, Daytona, Vercel Sandbox backends), usable for coding tasks among many others but not itself a dedicated coding agent.

**License / open-source status:** Open, MIT License per both repos' README/docs (not independently verified by reading raw LICENSE file bytes -- only via a page-fetch summary).

**Verdict:** Real and useful, but narrower than its "self-evolving" marketing implies -- and worth reading with that gap in mind. Everything that changes automatically today is markdown text (two memory files and skill files), gated by an optional human-approval queue, not code, not the base system prompt, and not tool permissions; the project's own architecture doc states this limitation plainly, in some tension with its skills/memory docs' description of an automatic post-turn "background review" pass. The actually-built evolutionary optimizer (DSPy+GEPA) lives in a separate sister repo, implements only the first of five planned phases (skill-text mutation), and is designed to always land as a human-reviewed pull request, never an autonomous deployment. No concrete before/after results from a real optimization run, and no independent third-party validation of the design, were found -- all efficacy claims are descriptive documentation, not demonstrated outcomes. Everything above comes from a web-fetch tool's LLM-summarized rendering of GitHub/docs pages, not from directly reading raw `.py` source.

## deepseek-ai/deepseek-harness ("dsh")

**What it is:** A real, currently-existing coding/tool-using agent harness (CLI + local web UI + headless mode) released by DeepSeek AI as a developer preview, built as a "plugin-everything" architecture on top of Cordis, a pre-existing, independently verifiable TypeScript meta-framework from the Koishi/cordiverse project (with its own published paper on "spatiotemporal composability"). It postdates this research's knowledge cutoff, so everything about it rests on this round's live fetches, not prior training knowledge.

**License / open-source status:** Open, MIT License per its README -- but not open-*contribution*: its own `CONTRIBUTING.md` states it cannot accept external pull requests at the moment.

**Verdict:** A genuinely deep, internally consistent architecture (turn/step execution model, an append-only typed session log as sole source of truth with `deriveMessages()` deriving model-visible history from it, a named multi-phase tool-execution pipeline, and Cordis's reversible-effects-as-contract plugin model) -- terminology across independently fetched pages (SessionEvents, `concludesTurn`, seams, waterfalls) is specific and mutually consistent in a way that reads as real documentation rather than invention. Its one genuinely self-modifying feature -- a running agent writing JavaScript and mounting it as a new plugin into its own live runtime via `cordis_define`/`cordis_run`, sandboxed with `node:vm` -- is real and documented, but is an explicitly separate, off-by-default extension package, not a core always-on behavior, and outside commentary calling this "RSI" (recursive self-improvement) is hype layered on top of a real but narrower opt-in capability that the project's own materials describe more conservatively. Nothing here was verified beyond secondhand page fetches (which themselves proxy through a summarizing layer) -- no raw source diff was read byte-for-byte, and no safety/approval gating around the self-modification tools could be confirmed beyond a vague reference to "the restricted repository Plugin runtime." Note also: this repo's own source-policy validation (see `self_evolution_patterns.md` and `delegation_and_composability.md`) deliberately forbids the dynamic-execution and protected-runtime-bypass patterns that deepseek-harness's live-plugin-mounting feature depends on -- so that specific mechanism is not something a harness here can adopt directly, only the higher-level design ideas (seams, reversible effects, session-log-as-truth) it demonstrates.
